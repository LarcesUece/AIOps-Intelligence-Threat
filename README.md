# AIOps-Intelligence-Threat

A threat intelligence analysis system based on AIOps (Artificial Intelligence for IT Operations) that uses machine learning techniques for IP classification and suspicious behavior analysis.

## Prerequisites

- Python 3.12 or higher
- `uv` package manager

## Installation

### Step 1: UV Installation

The project uses the `uv` package manager for faster and more efficient dependency management.

#### On Linux/macOS:
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

#### On Windows:
```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

#### Installation verification:
```bash
uv --version
```

### Step 2: Project Cloning and Configuration

```bash
# Clone the repository
git clone https://github.com/LarcesUece/AIOps-Intelligence-Threat.git
cd AIOps-Intelligence-Threat

# Switch to development branch
git checkout develop

# Install dependencies
uv sync
```

This will automatically create a virtual environment and install all dependencies listed in `pyproject.toml`.

### Step 3: Data Preparation

```bash
# Create the datasets folder (if it doesn't exist)
mkdir -p datasets

# Place your data files in the datasets/ folder
```

### Step 4: Virtual Environment Activation

```bash
# Activate the virtual environment created by uv
source .venv/bin/activate  # Linux/macOS
# or
.venv\Scripts\activate     # Windows
```

## System Usage

The project has **three main pipelines** that must be executed in order:

1. **Threat Analysis Pipeline** (`full_analysis_pipeline.py`)
2. **ML Training Pipeline** (`main.py`)
3. **IP Query Pipeline** (`query.py`)

### Pipeline 1: Threat Analysis (full_analysis_pipeline.py)

**First Step**: Execute the threat analysis pipeline

```bash
# Run the analysis pipeline
python full_analysis_pipeline.py
```

or using uv:

```bash
uv run python full_analysis_pipeline.py
```

#### Analysis Pipeline Phases

**Phase 1: Weight Calculation**
- Calculates final weights for features used in classification
- Saves results in `weights/final_weights.json`
- Uses the `calculate_final_weights()` function from the `src.feature_weight_calculator` module

**Phase 2: IP Classification**
- Classifies IPs and generates visualizations
- Uses weights calculated in the previous phase
- Generates the `datasets/dataset_ip_classified.csv` file (required for Pipeline 2)
- Uses the `classify_ips_and_generate_plots()` function from the `src.ip_classification` module

### Pipeline 2: Machine Learning Training (main.py)

**Second Step**: Execute the ML model training pipeline

This pipeline uses the classified dataset (`dataset_ip_classified.csv`) generated in Pipeline 1.

```bash
# Run the ML pipeline (both experiments)
python main.py
```

or using uv:

```bash
uv run python main.py
```

#### Experiment Types

The system automatically runs **two experiments**:

1. **Experiment WITHOUT SMOTE**:
   - Uses class_weight="balanced" to handle imbalance
   - Name: `experiment_WITHOUT_smote_corrected`

2. **Experiment WITH SMOTE**:
   - Applies SMOTE for synthetic balancing
   - Removes class_weight to avoid double balancing
   - Name: `experiment_WITH_smote_corrected`

#### Trained Models

The pipeline trains and evaluates the following models:

- **Random Forest**: Ensemble of decision trees
- **SVM**: Support Vector Machine with RBF kernel
- **Neural Network (MLP)**: Multi-layer neural network
- **Extra Trees**: Extremely randomized trees
- **Decision Tree**: Simple decision tree
- **KNN**: K-Nearest Neighbors with PCA
- **CNN**: 1D Convolutional Neural Network

#### ML Pipeline Phases

1. **Loading and Preprocessing**:
   - Loads `dataset_ip_classified.csv`
   - Removes null values
   - Normalizes feature scores

2. **Data Preparation**:
   - Train/test split (80%/20%)
   - SMOTE application (if enabled)
   - Label encoding

3. **Model Training**:
   - Grid Search with cross-validation
   - Hyperparameter optimization
   - Data leakage prevention

4. **Evaluation and Visualization**:
   - Performance metrics
   - Learning curves
   - Confusion matrices
   - Model comparison

### Pipeline 3: IP Query and Prediction (query.py)

**Third Step**: Execute classification queries for new IPs

This pipeline uses trained models to classify new IP sets.

```bash
# Basic usage (uses default dataset)
python query.py
```

or using uv:

```bash
uv run python query.py 
```

#### Query Functionalities

1. **Automatic Normalization**: Applies weights and normalization to new data
2. **Multi-model**: Tests all available models or a specific one
3. **Performance Comparison**: Measures execution time for each model
4. **Class Distribution**: Shows how many IPs were classified in each category

## Features

### Threat Analysis Pipeline
- **IP Classification**: Identifies suspicious and malicious IPs
- **Behavior Analysis**: Detects anomalous traffic patterns
- **Weight Calculation**: Determines the importance of different features

### Machine Learning Pipeline
- **Multi-model Training**: 7 different algorithms
- **Hyperparameter Optimization**: Automated Grid Search
- **Data Leakage Prevention**: Corrected pipeline without leakage
- **Class Balancing**: SMOTE vs class_weight
- **Robust Evaluation**: Multiple metrics and cross-validation

### Query and Prediction Pipeline
- **Real-time Query**: Classification of new IPs
- **Multi-model**: Support for all trained models
- **Automatic Normalization**: Consistent weight application
- **Performance Analysis**: Speed comparison between models
- **Batch Prediction**: Processing multiple IPs simultaneously

## Logs and Monitoring

### Analysis Pipeline
- Detailed log in `outputs/full_pipeline.log`
- Start and end timestamps for each phase
- Total execution time
- Detailed errors and exceptions

### ML Pipeline
- Detailed log in `data/experiments/*/experiment_log.txt`
- Information for each training step
- Performance metrics per model
- Executive summary in `experiment_summary.txt`

### Query Pipeline
- Detailed log in `outputs/model_prediction.log`
- Performance comparison between models
- Execution time for each prediction
- Class distribution report

## Error Handling

### Analysis Pipeline
- Captures and logs exceptions from each phase
- Stops execution in case of critical failure
- Provides detailed error messages

### ML Pipeline
- Robust error handling per model
- Continues execution even if one model fails
- Validation of required dataset existence

### Query Pipeline
- Robust handling of models not found
- Validation of required features in new data
- Detailed logs for prediction debugging

**Important Notes**: 
- **Mandatory Execution Order**: Pipeline 1 → Pipeline 2 → Pipeline 3
- **Pipeline 1**: Generates `datasets/dataset_ip_classified.csv` required for Pipeline 2
- **Pipeline 2**: Generates saved models required for Pipeline 3
- **Pipeline 3**: Requires trained models to function
- **weights/ folder**: Located at the same level as `src/` and `datasets/` folders
